# The `council` order-effect primary

**Audience:** the evaluating reader.

Eight draws per ordering per item, both orderings, all eleven measured items.
176 draws. Unaided, `sonnet`, blind. The primary is the **second-position
rate**; the flip rate is superseded and is not computed here.

Two sets, reported apart and never pooled:

- the **nine admitted items** (K04–K08, K10–K13), which the admission screen
  passed and which are the pre-registered primary;
- the **two recorded-stratum items** (K03, K09), which the screen rejected for
  disagreeing under a single ordering. Their within-ordering instability is a
  covariate column here, not a disqualifier.

The separation is enforced in the item metadata rather than in a filter, so the
same refusal that stops two arms being pooled into one rate stops these two sets
being pooled into one rate.

## What was run

- `primary_runner.py` — the runner. Discovers the measured corpus from disk,
  strips every item to `prompt` and `format_contract`, writes both orderings of
  all eleven items to `prompts/<opaque>.txt` under opaque ids shuffled together
  with seed `20260826`, shuffles the 176 draws into one issue order under seed
  `20260827`, and issues each call in a fresh working directory because the
  CLI's auto-memory path is keyed on cwd.
- `analyse.py` — reads the recorded replies and prints the report. It spends no
  calls, so a changed scorer is re-run over the replies rather than over the
  quota.
- `records/<opaque>-d<n>.json` — the draw, verbatim, with its isolation receipt,
  cost, duration and session id. `records/<opaque>-d<n>-a<k>.json` — every
  attempt at that draw, including the failed ones and the kind of failure.
- `battery-before.txt`, `battery-after.txt` — `python council_primary.py` either
  side of the two defect fixes.
- `report.txt` — the run, regenerated by `python analyse.py`.

## The isolation receipt, per draw

The screen asserted isolation once, on a smoke call. Here every draw runs under
`--input-format stream-json` and reads its own `system`/`init` event. A draw
whose receipt declares any tool, any skill or any slash command is recorded as a
failure and is not a datum. `smoke-init.json` holds the pre-run check, and that
call is not a draw.

## Blindness

Nothing in the bytes the model sees carries an item id, a stratum, a
`known_defects` list, a screen verdict, an answer key or a computed check. Both
orderings of an item are named by opaque ids drawn from one shuffle, so neither
a file listing nor id adjacency pairs an AB with its BA. Audited before the run:
twenty-two prompt files, zero violations, and each item's AB and BA prompts are
the same length to the byte.

## The two defects the screen left open, and what closing them cost

**The `NO_CALL` parse.** Two K09 screen draws were scored `NO_CALL` for writing
a markdown `---` between `CALL` and `GROUNDS`. Both had committed. That is the
exclusion law: a record leaves for emitting a horizontal rule, `council.md` asks
for more structured output, a structured arm rules off more often — so the
attrition is arm-correlated and runs **high on the treatment**. The extractor
now drops thematic breaks before it locates the call, never after, so nothing in
the fix can see which course was named. Re-scoring the screen's own records moves
one item's outcomes (K09, `no_call/no_call/first` → `first/second/first`) and no
item's verdict.

**The admission rule.** The registration named `BALANCED` as a call and was
silent on `NO_CALL`, `OFF_MENU` and `AMBIGUOUS`, so a literal reading admits an
item on four unanimous `NO_CALL` draws — an item the model never committed on,
promoted for being consistently unreadable. `screen_verdict()` in
`council_primary.py` now says so explicitly and rejects on sight. No candidate
drew four of anything unresolved, so no verdict on record moves.

Both are covered by new battery checks. 54 checks before, 65 after, 0 failures
either side.
