# The `council` admission screen, first run

**Audience:** the evaluating reader.

Four draws per item under one pre-registered ordering, AB only. Unanimity
admits. Early stop on the first disagreement. `BALANCED` counts as a call.
Unaided, `sonnet`, blind. Screen draws are discarded from the primary and may
never be reused as data.

## What was run

- `screen_runner.py` — the runner. Discovers the measured corpus from disk,
  strips every item to `prompt` and `format_contract`, writes those to
  `prompts/<opaque>.txt` under opaque ids shuffled with seed `20260825`, and
  issues each call in a fresh working directory because the CLI's auto-memory
  path is keyed on cwd.
- `analyse.py` — reads `screen-results.json` and prints the report. It spends no
  calls, so a changed scorer is re-run over the recorded replies rather than
  over the quota.
- `records/<opaque>-d<n>.json` — every reply verbatim, with its cost, duration
  and session id.
- `battery-before.txt` — `python council_primary.py` before any call was spent.
  54 checks, 0 failures, exit 0.
- `verify-block-a.txt`, `verify-block-b.txt` — the two block verifiers.

## The isolation receipt

The smoke call ran under `--input-format stream-json` so the CLI's
`system`/`init` event could be read before any screen draw was issued. It
declared `tools: []`, `skills: []`, `slash_commands: 0`, `model:
claude-sonnet-4-6`. The runner refuses to issue a screen draw when either
`tools` or `skills` is non-empty. The receipt is in `smoke-init.json`, and that
call is not a screen draw.

## Result

Nine of eleven admitted on 41 calls. Every exclusion count, the commit rate and
the power the admitted set delivers are in `report.txt`, regenerated by
`python analyse.py` over the recorded replies.

Two things this run found that are not in the numbers.

**`NO_CALL` fired twice, on a markdown horizontal rule.** Both are K09, both
land in the class the note already names as mixing a competence-positive
population with a competence-negative one. The model wrote `CALL`, the course
name, then `---` as a separator before `GROUNDS`; the shipped extractor reads a
second line in the block as "carried more than the call" and returns `NO_CALL`.
The reply committed. Under a rule-tolerant read K09's three draws are
`CRANMOOR / ELSWICK / CRANMOOR`, so **K09 is rejected either way** and the
verdict does not depend on the parse. What the parse cost was one extra call:
two `NO_CALL` draws agree with each other, so unanimity survived to draw three.
The scorer was not changed, because it is the battery-gated artefact and the
verdict does not turn on it. It is recorded here as an open item: at 2 of 41
draws this is a 4.9% attrition rate on a surface convention, and the primary
would carry it into the Manski bound.

**Four unanimous `NO_CALL` draws would admit an item.** The registration says
`BALANCED` counts as a call for unanimity and says nothing about the three
unresolved classes, and the runner implements the rule as written. An item the
model never committed on would pass the screen. It did not fire here — no item
drew four `NO_CALL` — so no verdict in this run is affected, and it is a hole in
the specification rather than in this run.

**The item files still say `verdict: not run` and `admitted: false`.** Admission
is recorded in `screen-results.json` alone, because this run was scoped to write
only under `screen-run/`. Carrying the verdicts back into the item blocks is the
follow-up.
